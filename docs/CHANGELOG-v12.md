## หน้าบ้าน: ไฟล์เดียว 530KB / 7,528 บรรทัด → โครงหน้า + 36 ไฟล์
| ก่อน | หลัง |
|---|---|
| `index.html` ก้อนเดียว: CSS + HTML + สคริปต์ 11 ก้อน | `index.html` 1,192 บรรทัด (markup อย่างเดียว) + `css/app.css` + `js/<หมวด>/…` 33 โมดูล + `js/boot/` 3 ไฟล์ |
| โค้ดหลัก 3,192 บรรทัดในก้อนเดียว | แบ่งตามหน้าที่ (ขาย/สต็อก/ตั้งค่า/ซิงค์/ล็อกอิน/กะ) ไฟล์ละ 24–543 บรรทัด |
| ไม่รู้ว่าฟังก์ชันที่ปุ่มเรียกอยู่ตรงไหน | หัวไฟล์ทุกไฟล์บอกหน้าที่ + ลิสต์ `window.*` (อัปเดตอัตโนมัติ `npm run headers`) |
| ลืมเพิ่มไฟล์/syntax ผิดจึงรู้ตอนเปิดแอป | `npm run check` ตรวจ manifest, syntax, ไฟล์ตกหล่น, inline script/style ที่หลุดเข้ามา |
| ไม่มี loader error ที่เข้าใจได้ | ถ้าโหลดโมดูลไม่สำเร็จ แสดงข้อความภาษาไทยบอกไฟล์ที่ขาด + วิธีแก้ |
- **พิสูจน์ว่าไม่เปลี่ยนพฤติกรรม:** การแยกไฟล์เทียบ token ของโค้ดก่อน/หลัง ครบ 50,723 ตัวเหมือนเดิมทุกตัว (เปลี่ยนเฉพาะช่องว่าง/ลดการเยื้อง และแยก IIFE เดิมที่ครอบหลายส่วนเป็น 2 ก้อน)
- ลบโค้ดที่ไม่มีใครเรียก: shim `syncBillToSupabaseRPC` / `syncReturnToSupabaseRPC` / `syncGoodsReceiptToSupabase` และตารางแม็ปหมวด Excel เก่า
- service worker อ่านรายการไฟล์จาก `pos-manifest` (แหล่งความจริงเดียว) · `?v=<version>` กันแคชเก่า

## ใช้งานง่ายขึ้น
- **✅ ตรวจความพร้อมก่อนใช้งานจริง** (ตั้งค่า > ร้านค้า): สรุปเป็นภาษาคนว่าอะไรต้องแก้ — ราคาขาย 0, ไม่มีราคาทุน, สต็อก 0/ติดลบ, ยังไม่ตั้ง PIN, ยังไม่ล็อกอินร้าน, schema เก่า, คิวค้าง/ถูกปฏิเสธ, ยังไม่เปิดบัญชีรายพนักงาน/ป้องกันสต็อกติดลบ
- เปลี่ยนชื่อหน้าเว็บเป็น "Smart POS — YOJIONLINE" (เดิมค้างเป็น V9.60)

## เครื่องมือพัฒนา
`npm run dev` (เซิร์ฟเวอร์ทดสอบ) · `npm run check` · `npm run headers` · เทสต์ 60 ข้อ รวมเทสต์ "บูตจริง" ที่โหลดโมดูลทั้ง 33 ไฟล์ผ่านตัวโหลด

## ข้อจำกัด
ยังไม่ได้เปิดแอปในเบราว์เซอร์จริง (หน้าตา/ปุ่ม/กล้อง) · `schema.sql` และ `pin-login` ยังไม่ได้รันกับ Supabase จริง · ไม่ได้จัดรูปแบบโค้ดด้วย formatter อัตโนมัติ (ไม่มีเครื่องมือในเครื่อง — ทำได้เพียงลดการเยื้อง/จัดหัวไฟล์) · markup ใน index.html ยังเป็นไฟล์เดียว (~1,100 บรรทัด)

## 12.0.1 — แก้ซิงค์ครั้งแรกล้ม (พบจากการใช้งานจริง)
- **อาการ:** ตั้งเจ้าของร้านสำเร็จแล้ว กดซิงค์ขึ้น "เกิดข้อผิดพลาดในการซิงค์ — ซิงค์สินค้า/หมวดหมู่/ลูกค้าไม่สำเร็จ"
- **สาเหตุ:** `bootstrap_first_owner` สร้างแถวเจ้าของด้วย id ที่เซิร์ฟเวอร์สุ่ม แต่เจ้าของในเครื่องใช้ id ของตัวเอง ตอนซิงค์แอปจึงพยายามเพิ่ม "เจ้าของคนที่สอง"
  → ชนดัชนี `idx_app_users_one_owner` → ซิงค์ทั้งชุดล้ม (บั๊กนี้มีมาตั้งแต่ก่อนรวมไฟล์ ไม่ได้เกิดจากการแยกโมดูล)
- **แก้:** ตั้งเจ้าของแล้วใช้ id ที่เซิร์ฟเวอร์ส่งกลับ (`adoptServerUserId`) · เครื่องที่ตั้งไปแล้วจะปรับ id ให้ตรงอัตโนมัติก่อนซิงค์ (`reconcileOwnerId`) — ไม่ต้องรัน SQL เพิ่ม
- **แสดงสาเหตุจริง:** เดิมกล่อง error ที่มีรายละเอียดถูกกล่องทั่วๆ ไปทับ → ตอนนี้แสดงข้อความ + รายละเอียด + คำแนะนำ + รหัส (`describeError`), กล่องเลื่อนอ่านและแตะค้างคัดลอกได้
- เทสต์ใหม่ 6 ข้อ (รวมเทสต์ที่จำลองบั๊กเดิมและพิสูจน์ว่าล้มเมื่อปิดตัวแก้) — ทั้งชุด 66 ข้อ
