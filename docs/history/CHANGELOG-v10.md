## ฝั่งแอป (public/index.html)
| ปัญหาเดิม | การแก้ |
|---|---|
| เลขบิลซ้ำข้ามเครื่อง / ทับบิลกัน / ใช้วันที่ UTC | `POS-YYYYMMDD-<รหัสเครื่อง>-NNN` วันที่เวลาไทย (GR/CN ก็เช่นกัน) |
| ส่วนลดไม่ถูกบันทึก/ไม่ส่งขึ้นเซิร์ฟเวอร์ | บิลเก็บ `subtotal`/`discount`, ส่ง `p_discount_amount` + `p_expected_total` |
| ยอดรวมอ่านจากข้อความบนจอ (≥ 1,000,000 เพี้ยน) | คำนวณจาก state ด้วย `calcCartTotals` (ใช้ทั้งหน้าขาย QR เงินทอน) |
| คืนสินค้าไม่หักส่วนลด | คืนตามสัดส่วนที่จ่ายจริง (`billRefundRatio`) ทั้งหน้าจอและเซิร์ฟเวอร์ |
| fallback เขียนบิลตรงข้ามกฎสต็อก/วงเงิน | **ยกเลิก** — ทุกธุรกรรมผ่านคิวซิงค์ (`db.syncQueue`) → RPC; ออฟไลน์=ค้างแล้วลองใหม่, เซิร์ฟเวอร์ปฏิเสธ=ติด failed + แจ้งเตือน |
| คืนสินค้า/รับชำระ/รับของ ไม่ retry, แถวเงินสดซ้ำ | เข้าคิวแบบ idempotent (`p_return_ref`, `p_op_ref`, `client_ref`) และไม่ส่ง ledger ซ้ำ (`_viaRpc`) |
| ซิงค์ทับสต็อก/หนี้ของเครื่องอื่น | ไม่ส่ง `stock_quantity`/`debt` ใน upsert; ส่งค่าตั้งต้นครั้งเดียว (seed) แล้วเปลี่ยนผ่าน RPC; ดึงข้อมูลแล้วปรับสต็อก/หนี้ตามเซิร์ฟเวอร์ (เมื่อไม่มีรายการค้าง) |
| ไม่เช็คสต็อกก่อนขาย | ตั้งค่า "ป้องกันสต็อกติดลบ" (ค่าเริ่มต้นปิด) ทั้งเครื่องและเซิร์ฟเวอร์ |
| วงเงินเครดิตไม่ตรง (เครื่อง 50,000 / เซิร์ฟเวอร์ 0) | ส่ง `creditLimit ?? 50000` |
| ลบสินค้าบนคลาวด์ไม่สำเร็จ / กลับมาตอน pull | ใช้ `delete_entity` (archive) ผ่านคิว + pull กรอง `is_active` |
| ต้นทุนรับของไม่ตรง SQL | ถัวเฉลี่ยถ่วงน้ำหนักเหมือนเซิร์ฟเวอร์ (`receive_goods`) |
| PIN: default 0000, SHA-256 ไม่มี salt, ลองไม่จำกัด | ไม่มี PIN เริ่มต้น (ตั้งเองครั้งแรก), PBKDF2-SHA256 150k รอบ + salt, อัปเกรด hash เก่าอัตโนมัติ, พักล็อกอินหลังผิด 5 ครั้ง, ห้าม PIN เดาง่าย |
| ไม่ล็อกอินแต่ถือว่าเป็นเจ้าของ / สำรอง-คืนค่า-ล้างเครื่องไม่เช็คสิทธิ์ | `canDo` ปฏิเสธเมื่อยังไม่ล็อกอิน (หลังตั้ง PIN แล้ว), 3 ฟังก์ชันเฉพาะเจ้าของ, ไม่บันทึก `activeUser` ลง localStorage |
| ตัวนำเข้า Excel ไม่ตรงไฟล์ | เขียนใหม่: จัดกลุ่มตามชื่อ (1,976 แถว → 1,439 สินค้า), อ่านขนาด/บาร์โค้ด EAN/SKU, สร้างหมวดจากไฟล์, id คงที่ (นำเข้าซ้ำ = อัปเดต ไม่ล้างสต็อก), พรีวิว+คำเตือน |
| `window.formatMoney` ไม่มี, onclick ฝัง URL (XSS), CDN ไม่ล็อกเวอร์ชัน, ไม่มี offline | แก้ครบ + `sw.js` |

## ฝั่งฐานข้อมูล (0002_fixes.sql)
idempotent RPC ทั้งชุด · ตรวจส่วนลด/จำนวน/ราคา(บันทึก audit `PRICE_MISMATCH`/`TOTAL_MISMATCH`) · ล็อกแถวเรียง id กัน deadlock ·
กันคืนเกินจำนวนขาย (`bill_items.returned_qty`, `bill_returns`) · trigger ห้ามแก้สต็อก/หนี้ตรงๆ · ปิดสิทธิ์เขียนตรงบน bills/bill_items/inventory_movements ·
เขียนข้อมูลหลัก/บัญชีได้เฉพาะ manager · `search_path` ของ security definer · revoke execute จาก anon · `bootstrap_first_owner` ตรวจรูปแบบ hash + advisory lock

## ยังไม่ได้แก้ (ตั้งใจ — ดู GO-LIVE-CHECKLIST)
- RLS แยกบทบาทแคชเชียร์/ผู้จัดการ ยังไม่มีผลจริง เพราะทุกเครื่องล็อกอิน Supabase ด้วยบัญชีเจ้าของบัญชีเดียว (PIN เป็นด่านฝั่งเครื่อง) — ต้องทำ Edge Function ออก token รายพนักงาน
- ข้อมูลทั้งหมดอยู่ใน localStorage (~5MB) — ควรย้ายไป IndexedDB เมื่อบิลสะสม
- ใบรับของ 1 ใบ = variant แรกของสินค้า (ยังไม่มีตัวเลือกขนาดในหน้ารับของ)
- ลบลูกค้า/ซัพพลายเออร์/หมวดหมู่ ยังเป็น local-only · หมวดหมู่ย่อย (`parent_id`) ยังไม่ซิงค์
- CDN ล็อกเวอร์ชันแล้วแต่ยังไม่ใส่ SRI hash · รูปใบส่งของอยู่ใน bucket สาธารณะ · QR พร้อมเพย์เรียก `promptpay.io` ภายนอก
