# เช็กลิสต์ก่อนใช้งานจริง (ทำบนโปรเจกต์ Supabase ทดสอบก่อน)

## ก่อนเริ่ม
- [ ] เปิดแอป → ตั้งค่า > ร้านค้า → กด **✅ ตรวจความพร้อมก่อนใช้งานจริง** ต้องไม่มีข้อ ❌

## A. ฐานข้อมูล
- [ ] รัน `supabase/schema.sql` ไม่มี error · `select pos_schema_version();` = 3 (รันซ้ำอีกครั้งต้องไม่มี error)
- [ ] ปิด public sign-up · เปิด Security Advisor แล้วไม่มี error ระดับสูง
- [ ] ลอง `update product_variants set stock_quantity = 99` ด้วย session ผู้ใช้ → ต้องถูกปฏิเสธ (trigger)

## B. สถานการณ์ทดสอบ (ใช้ 2 เครื่อง/2 เบราว์เซอร์)
1. ขายสด ส่วนลด 10% → บิลบนเซิร์ฟเวอร์: `subtotal`, `discount_amount`, `total` ตรงกับใบเสร็จ
2. 2 เครื่องขายสินค้าตัวเดียวกันพร้อมกัน → สต็อกบนเซิร์ฟเวอร์ลดถูก ไม่ทับกัน, เลขบิลไม่ซ้ำ
3. ปิดเน็ต ขาย 3 บิล → ป้าย ⏳ รอส่ง 3 → เปิดเน็ต → ส่งครบอัตโนมัติ, ไม่มีบิลซ้ำเมื่อกดซิงค์ซ้ำ
4. ขายเชื่อเกินวงเงิน → ถูกปฏิเสธ ป้าย ⚠️ ติด failed (ไม่ถูกเขียนข้ามกฎ)
5. คืนสินค้าบิลมีส่วนลด → ยอดคืน = สัดส่วนที่จ่ายจริง; คืนเกินจำนวนที่ขาย → ถูกปฏิเสธ; กดซ้ำ → ไม่คืนซ้อน
6. รับชำระหนี้ → หนี้ลดครั้งเดียว, `cash_ledger` มีแถว `cash-in-ar` แถวเดียว
7. รับของเข้า (ต้นทุนใหม่) → ต้นทุนถัวเฉลี่ยตรงกันทั้งเครื่องและเซิร์ฟเวอร์
8. ปรับสต็อกหลายรายการ / แก้จำนวนในหน้าสินค้า → เซิร์ฟเวอร์ตรง, `inventory_movements` มีเหตุผล
9. ปิดกะ → ยอดเงินสด = ขายสด + รับชำระ − คืนเงิน ± เงินเข้า/ออก
10. ดึงข้อมูลจากคลาวด์บนเครื่องใหม่ → สินค้า/สต็อก/หนี้/บิลถูกต้อง สินค้าที่ลบแล้วไม่กลับมา
11. กู้คืนไฟล์สำรอง / ล้างเครื่อง ด้วยบัญชีแคชเชียร์ → ต้องถูกปฏิเสธ
12. ผิด PIN 5 ครั้ง → พักล็อกอิน
